# Hongming Tan Blog

A static, component-aware Markdown publishing system for GitHub Pages. Markdown is compiled to semantic HTML first; Vite then bundles browser modules, CSS, and assets into `dist/`.

## Architecture

```text
articles/<slug>/
├── index.md
├── assets/
└── components/          # optional article-private components

components/              # public writing components
themes/                  # Markdown presentation and layout
core/build/               # Markdown AST and compatibility validation
core/client/              # shared progressive enhancement
styles/site-header.css    # shared homepage/article site chrome
tools/build-content.mjs   # article and metadata generator
index.html                # generated publication-style article homepage
dist/                     # generated GitHub Pages artifact
artifacts/                # ignored local archive; never shipped or synced
```

The build has two stages:

1. `tools/build-content.mjs` parses Markdown, validates component/Theme compatibility, generates each article's `index.html` and static `article-entry.js`, then rebuilds the root article homepage from the same metadata.
2. Vite follows those static module imports, rewrites asset URLs, hashes CSS/JS, and writes the deployable site to `dist/`.

No server runtime is required.

The root `index.html` is generated by `core/build/home.mjs`; do not edit its article list by hand. Production entry points are deliberately limited to this homepage and `articles/<slug>/index.html`.

## Commands

```bash
npm install
npm run dev
npm run build
npm run preview
```

Validation used by CI:

```bash
npm run content:check
npm run build
```

`npm run dev` regenerates existing articles when Markdown, Theme, or component files change. Restart the dev server after adding an entirely new article directory so Vite can add its HTML entry.

## Writing an article

Create `articles/<slug>/index.md`:

```markdown
---
title: Sparse Feature Geometry
date: 2026-07-21
category: Research
summary: Optional index and page description.
author: Hongming Tan
affiliation: Independent Researcher
theme: distill
---

## First section

Article content.
```

Asset paths are local to the article:

```markdown
![Figure title | A descriptive caption.](./assets/figure.svg){wide}
```

Supported figure modifiers are `{wide}`, `{full}`, and percentage widths such as `{70%}`.

Current Theme:

- `distill`: Transformer Circuits-inspired research layout with a centered research title, compact citations, and structured end matter. It does not render a table of contents.

The Theme manifest declares capabilities in `themes/distill/theme.yaml`. The content build rejects a component whose requirements are not provided by the selected Theme. The loader remains extensible, but `distill` is currently the only supported and default Theme.

## Components

Use a public component:

```markdown
:::component{name="shared.callout" title="Observation" tone="claim"}
The body remains ordinary Markdown.
:::
```

Use an article-private component:

```markdown
:::component{name="local.my-figure" source="./assets/data.json"}
Optional Markdown body.
:::
```

Every component must contain:

```text
component-name/
├── component.yaml       # name, scope, capabilities, Theme restrictions
├── index.mjs            # build-time render() export
├── README.md            # authoring documentation
├── style.css            # optional
├── client.js            # optional hydrate() export
└── examples/            # recommended Markdown fixtures
```

Browser code must use ESM. The generated `article-entry.js` contains static imports so Vite can bundle private modules correctly for GitHub Pages. Do not construct production module URLs from arbitrary Markdown strings.

## Footnotes, references, math, and code

Footnotes use standard Markdown:

```markdown
The convention varies by market.[^efp]

[^efp]: This article uses futures minus physical spot.
```

Numbered references retain the existing writing syntax:

```markdown
This sentence cites a source [1].

[1]: Author, Title, Year. https://example.com/source
```

Grouped citations are also supported: `[1, 2]`. Hovering or focusing a citation shows a compact source preview.

Use numbered references for evidence, claims, reports, papers, videos, and other source material. This keeps prose as ordinary text and places a compact citation marker after the claim:

```markdown
The measured ratio continued to fall [1].

[1]: Dataset or report title. https://example.com/source
```

Reserve ordinary Markdown links such as `[Open the notebook](https://example.com/notebook)` for destinations the reader is intentionally expected to open: notebooks, repositories, tools, downloads, and navigation. The Distill Theme renders these direct links as subdued text with a thin underline rather than citation blue.

End-matter headings use ordinary Markdown. `Appendix`, `Acknowledgements`, `Acknowledgments`, `Author Contributions`, and an optional custom `Citation Information` section are moved to the shaded end-matter grid. Standard Markdown footnotes and numbered references follow automatically. `Discussion`, `Comments`, and `Replications` stay in the main reading flow; use `shared.comment` for a styled response block (see `components/comment/README.md`).

The generated citation can be overridden in front matter:

```yaml
citation:
  author: Hongming Tan
  venue: Hongming Tan
  url: https://harmonytan.github.io/articles/example/
  key: tan2026example
```

Math supports `$...$`, `$$...$$`, `\(...\)`, and `\[...\]`. KaTeX renders it during the content build, so formulas remain visible without article JavaScript.

## Deployment

The GitHub Pages workflow installs locked dependencies, builds `dist/`, and uploads that directory as the Pages artifact. Vite uses relative asset URLs (`base: "./"`), so nested article routes work both on user Pages and project Pages paths.

The old runtime, retired redirect shells, and unpublished local drafts are kept only in `artifacts/`. That directory is ignored by Git and excluded from Vite, so it is a local quarantine rather than a backup. Production code must never import from it.
